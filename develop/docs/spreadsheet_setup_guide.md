# スプレッドシート & GAS 環境構築手順書

対象読者: 情報システム部（保守担当）
所要時間目安: 30〜45分

---

## STEP 1. Googleスプレッドシートを新規作成する

1. Googleドライブで **新規 > Google スプレッドシート** を作成。
2. ファイル名を `フットサルリーグ_DB_2026` のようにわかりやすく変更する。
3. このスプレッドシートが唯一のデータベース（Tournaments / Teams / Users / Matches / Match_Events）になる。

> **重要**: このスプレッドシートに **紐づくコンテナバインドスクリプト** として GAS を作成するため、
> 「拡張機能 > Apps Script」から作成すること（単独のスタンドアロンスクリプトは使わない）。

---

## STEP 2. Apps Script プロジェクトを作成し、5ファイルを配置する

1. スプレッドシートのメニューから **拡張機能 > Apps Script** を開く。
2. デフォルトで存在する `コード.gs`（または `Code.gs`）に、`backend/main.gs` の内容を丸ごと貼り付ける。
   - ファイル名は `main.gs` に変更しておく（拡張子 `.gs` は自動付与）。
3. 左側の「＋」から **スクリプト** を追加し、以下4ファイルを同様に作成・貼り付ける。
   - `spreadsheet.gs`
   - `auth.gs`
   - `schedule.gs`
   - `ranking.gs`
4. 保存（Ctrl+S / Cmd+S）する。

最終的なファイル構成:
```
main.gs
spreadsheet.gs
schedule.gs
ranking.gs
auth.gs
```

---

## STEP 3. シートを自動初期化する

1. Apps Script エディタ上部の関数選択ドロップダウンで `setupSheets` を選択。
2. **実行** ボタンを押す。
3. 初回実行時は権限承認画面が出るので、自分のGoogleアカウントで承認する
   （「このアプリは Google で確認されていません」→ 詳細 → 安全でないページに移動 で進める）。
4. スプレッドシートに戻り、以下5シートが自動生成されていることを確認する。

| シート名 | 主なカラム |
| :--- | :--- |
| Tournaments | tournament_id, name, event_date, status, courts, schedule_status |
| Teams | team_id, tournament_id, name, type, status |
| Users | user_id, team_id, name, department |
| Matches | match_id, tournament_id, start_time, end_time, court_name, home_team_id, away_team_id, home_score, away_score, status, updated_by, updated_at |
| Match_Events | event_id, fiscal_year, match_id, team_id, user_id, points |

### （任意・推奨）入力規則（プルダウン）の設定

データ品質を上げるため、以下の列に **データ > データの入力規則** でプルダウンを設定しておくと安心です。

| シート | 列 | 選択肢 |
| :--- | :--- | :--- |
| Tournaments | D（status） | PLANNING / IN_PROGRESS / FINISHED |
| Tournaments | F（schedule_status） | 空欄 / DRAFT / CONFIRMED |
| Teams | D（type） | SINGLE / JOINT |
| Teams | E（status） | PENDING / APPROVED |
| Matches | J（status） | SCHEDULED / FINISHED |

---

## STEP 4. 管理者パスワードをスクリプトプロパティに設定する（推奨）

設計書のデフォルト値 `ilovefutsal` をそのまま使うこともできますが、
ソースコードに平文で残さないよう、スクリプトプロパティへの設定を推奨します。

1. Apps Script エディタ左メニューの **プロジェクトの設定**（歯車アイコン）を開く。
2. **スクリプト プロパティ** > **スクリプト プロパティを追加**。
3. プロパティ: `ADMIN_PASSWORD` / 値: 任意の運用パスワード を設定して保存。

（未設定の場合は `auth.gs` の `getAdminPassword()` が自動的に `ilovefutsal` にフォールバックします）

---

## STEP 5. 期限切れトークンの自動掃除トリガーを設定する（任意）

1. Apps Script エディタ左メニューの **トリガー**（時計アイコン）を開く。
2. **トリガーを追加**。
3. 実行する関数: `cleanupExpiredTokensTrigger`
4. イベントのソース: `時間主導型` / 時間ベースのタイマー: `時間タイマー` / `1時間おき`
5. 保存する。

---

## STEP 6. Webアプリとしてデプロイする

1. Apps Script エディタ右上の **デプロイ > 新しいデプロイ**。
2. 種類の選択で歯車アイコン → **ウェブアプリ** を選択。
3. 設定:
   - 説明: `futsal-league-api-v1`
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
4. **デプロイ** をクリックし、権限承認を行う。
5. 発行された **ウェブアプリURL**（`https://script.google.com/macros/s/xxxxx/exec`）をコピーする。

> **仕様更新時の注意**: `.gs` ファイルを修正したら、**デプロイを管理 > 編集 > 新しいバージョン** で
> 再デプロイしないと、公開中のURLには反映されません（URL自体は変わりません）。

---

## STEP 7. フロントエンドにAPI URLを設定する

`frontend/js/api.js` を開き、以下の行をSTEP 6で取得したURLに書き換える。

```js
const API_BASE_URL = "https://script.google.com/macros/s/xxxxxxxxxxxxxxxxxxxxxxxx/exec";
```

---

## STEP 8. GitHub Pages へフロントエンドを公開する

1. GitHubで新規リポジトリを作成（例: `futsal-league-frontend`）。
2. `frontend/` フォルダの中身（`index.html`, `css/`, `js/`）をリポジトリ直下にpushする。
3. リポジトリの **Settings > Pages** を開く。
4. Source を `Deploy from a branch`、Branch を `main` / `/(root)` に設定して **Save**。
5. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` でアクセス可能になる。

## 付録: 初期データを手動で投入する場合の列順

Tournamentsシートに1行だけ手動で大会を追加したい場合は、以下の順で入力してください
（`setupSheets()` 実行後、2行目以降に直接入力可能）。

```
TN_2026_01 | 2026年度 第1回大会 | 2026-07-31 | PLANNING | （courts列は空欄でOK） | （schedule_status列も空欄でOK）
```

`courts`列（E列）は、管理者ダッシュボードの「②コート予約」で保存すると、
コートごとの予約時間を含むJSON文字列（例: `[{"name":"Aコート","start":"19:00","end":"21:00"}]`）が
自動的に書き込まれます。`schedule_status`列（F列）は「④対戦表自動生成」の実行時に`DRAFT`、
「⑤対戦表の確認・確定」で確定した時点で`CONFIRMED`に自動更新されます
（`CONFIRMED`になるまで、一般参加者の画面には対戦表が表示されません）。
手動で大会行だけ作成する場合は、courts・schedule_status とも空欄のままで問題ありません。
